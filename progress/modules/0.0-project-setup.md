- **2026-07-23** — Scaffolded `app/` per docs/CONVENTIONS.md Section 1: Next.js 16.2.11 (App Router, TypeScript strict, Tailwind), module/lib/type stub folders, tests/, supabase/migrations/, .env.example (documents the server-only vs NEXT_PUBLIC_ convention plus the multi-key-pool env vars from docs/CONVENTIONS.md Section 5), ESLint (next/core-web-vitals + eslint-config-prettier) + Prettier, and the CI workflow + Dependabot config. Verified clean in this session: `tsc --noEmit`, `eslint .`, `prettier --check .`, and the test suite.
- **2026-07-23** — Testing tooling: used Node's built-in test runner (`node --test`, native TS type-stripping — zero extra dependency) instead of Vitest. Vitest reproducibly crashed with a native "Bus error" tied to its worker-pool/native-binary startup, reproduced across `--pool=threads` and `--pool=forks`, across Vitest v4 and v2, and with `useAtomics=false` — isolated to this build shell specifically (`node --test`, plain `worker_threads`, and plain `child_process.fork` all ran fine standalone). Documented so a future session doesn't re-add Vitest expecting a different result in the same environment without re-verifying first.
- **2026-07-23** — `next build` could not be verified to completion in this sandboxed shell, for the same underlying reason: Next's production-build worker process also crashed with SIGBUS, reproduced on both Next 15.5.21 and 16.2.11 (ruling out a version-specific bug) and independent of `experimental.cpus`/`workerThreads` settings. `next dev` (same SWC compiler, no build-time worker pool) ran fine, `tsc --noEmit`/`eslint`/tests all pass — isolating the fault to that one worker-spawning code path in this environment, not a code defect. Stayed on Next 16.2.11 (latest) since the crash isn't version-specific. The `.github/workflows/ci.yml` added this session runs the real build on a normal GitHub Actions runner once pushed — treat that as the actual build gate, not a local run in this sandbox.
- **2026-07-23** — Removed `next/font/google` (Geist/Geist Mono) from the default template; it requires a build-time fetch to Google Fonts for zero product benefit at this stage, and is one more thing that can fail a production build. Using Tailwind's default font-sans stack instead. Revisit with `next/font/local` if/when there's an actual brand typeface.
- **2026-07-23** — `git init` was attempted at the repo root but hit a stuck `.git/index.lock`, caused by the same mounted-drive filesystem limitation that affected npm's install earlier in this session (rename/unlink not fully supported from this sandbox onto the mounted D: drive). Removing the lock file requires user permission, which was declined when asked — git initialization is deferred to the user's own machine. All source files are on disk and correct regardless of git state.
