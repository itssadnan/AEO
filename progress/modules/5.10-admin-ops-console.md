## Purpose

Internal-only view of API quota usage and errors across all customers, and the admin surface for managing which AI model handles which task — globally and per custom-plan customer.

## Acceptance criteria

- [ ] Live Gemini + NVIDIA NIM quota consumption view, broken down per key in the pool (primary/secondary/tertiary), not just per provider
- [ ] Key-pool health view: which keys are alive vs. marked dead, when a key died, and a manual "clear dead flag" action for once it's resolved
- [ ] Displays current failoverMode ("shared" vs "emergency-only") per provider, with a visible reminder to switch to emergency-only the moment primary is upgraded to paid/higher-tier
- [ ] A key transitioning to dead (401/403) fires an immediate alert (not just a log line) — this is the loud-failure requirement from docs/CONVENTIONS.md
- [ ] Error/failure log for failed checks
- [ ] Basic churn signal: customers inactive 2+ weeks
- [ ] AI task config view: list every task key's current global-default (provider, model, enabled) from ai_task_configs, editable inline
- [ ] Enable/disable a model for a task globally (flips `enabled` on the global-default row)
- [ ] Per-workspace override: search a workspace, add/edit/remove its override row for any task key, without touching the global default
- [ ] Every write to ai_task_configs records updated_by + updated_at (who changed what, when) — this table has no customer-facing audit trail, so the admin log is the only one

## Tech

Internal-only Next.js route gated by an admin flag. Writes to ai_task_configs go through a server-side route using the Supabase service role (the table has no customer RLS to piggyback on — see the entity-relationship diagram).

## AI usage

None.

## Caching

Short TTL (e.g. 60s) on the quota-usage view is fine — it's an internal dashboard, not billing-critical, so a slightly stale read is an acceptable tradeoff for lower DB load.

## Security

Gate at the server/API layer by role check, not just by hiding a frontend link.
