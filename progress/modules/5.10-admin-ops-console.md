## Purpose

Internal-only view of API quota usage and errors across all customers, and the admin surface for managing which AI model handles which task — globally and per custom-plan customer.

## Acceptance criteria

- [x] Live Gemini + NVIDIA NIM quota consumption view, broken down per key in the pool (primary/secondary/tertiary), not just per provider (verified via migration 0019 + `onAttempt` slot callback + `quota-section.tsx`)
- [x] Key-pool health view: which keys are alive vs. marked dead, when a key died, and a manual "clear dead flag" action for once it's resolved (verified via `key-health-section.tsx` + `clearDeadKeyAction`)
- [x] Displays current failoverMode ("shared" vs "emergency-only") per provider, with a visible reminder to switch to emergency-only the moment primary is upgraded to paid/higher-tier (verified via `failover-mode-section.tsx` + `setFailoverModeAction`)
- [x] A key transitioning to dead (401/403) fires an immediate alert (not just a log line) — this is the loud-failure requirement from docs/CONVENTIONS.md (verified via `ADMIN_ALERT_WEBHOOK_URL` POST hook in `engine-worker/index.ts`'s `markKeyDead`)
- [x] Error/failure log for failed checks (verified via `error-log-section.tsx` rendering `engine_error_logs`)
- [x] Basic churn signal: customers inactive 2+ weeks (verified via `getChurnSignal()` joining `workspaces` -> `workspace_members` -> `auth.users.last_sign_in_at`)
- [x] AI task config view: list every task key's current global-default (provider, model, enabled) from ai_task_configs, editable inline (verified via `ai-task-configs-section.tsx`)
- [x] Enable/disable a model for a task globally (flips `enabled` on the global-default row) (verified via `upsertAiTaskConfigAction`)
- [x] Per-workspace override: search a workspace, add/edit/remove its override row for any task key, without touching the global default (verified via `ai-task-configs-section.tsx` + `deleteWorkspaceOverrideAction`)
- [x] Every write to ai_task_configs records updated_by + updated_at (who changed what, when) — this table has no customer-facing audit trail, so the admin log is the only one (verified via `upsertAiTaskConfig`)

## Tech

Internal-only Next.js route gated by `requireAdmin()` (checking server-only `ADMIN_USER_EMAILS` allowlist). Writes to `ai_task_configs`, `ai_provider_key_health`, `ai_provider_settings`, and `engine_error_logs` go through server-side routes/actions using the Supabase service role.
