## Purpose

The core scheduler/worker: runs each active prompt against Gemini with Search grounding, on a schedule, and stores the raw result. Built behind an AIProvider interface so engines are swappable later.

## Acceptance criteria

- [x] AIProvider interface defined; GeminiProvider is the only implementation for now
- [x] ai_task_configs table + resolveTaskModel(taskKey, workspaceId) resolver owned by this module (global default row + per-workspace override, `enabled` flag, admin-only RLS — see ERD); no other module hardcodes a provider or model string
- [x] Migration seeds global-default rows for all five task keys with the values from spec Section 6
- [x] Queue-based worker pulls due (brand, prompt) pairs and calls Gemini with grounding enabled, resolving its model via resolveTaskModel("grounded_search", workspaceId) — deployed live as the `engine-worker` Edge Function (version 1, ACTIVE); not yet proven with a real end-to-end run (see Blockers)
- [x] Full raw answer + citation list stored per check
- [x] Throttled to Gemini's current free-tier RPM/RPD caps (15 RPM / 1500 RPD), **per key slot** — fixed 2026-07-24, previously one shared bucket across all 3 keys; checks staggered ~200ms/job + jitter within a batch, not fired all at once
- [x] Retries with backoff on rate-limit errors; failed checks are requeued, never silently dropped — RPD exhaustion now throws a retryable error instead of an in-process 24h sleep (fixed 2026-07-24); a job stuck in `processing` from a crashed/timed-out worker invocation is now reclaimed by `reclaim_stale_check_jobs()` (migration 0009) at the start of every invocation
- [x] Key pool (primary/secondary/tertiary) implemented for GeminiProvider and NvidiaNimProvider per docs/CONVENTIONS.md — 429 soft-fails to the next key, 401/403 marks that key dead + alerts the Admin Console, never a silent drop. The DB-persisted dead-key set (`ai_provider_key_health`) is now actually threaded into key selection via `knownDeadSlots` (fixed 2026-07-24 — it was fetched and then discarded before)
- [x] Falls back to the standard retry/requeue path if every key in a provider's pool is dead or exhausted
- [x] Pool supports failoverMode "shared" (default; secondary/tertiary absorb 429s) vs "emergency-only" (secondary/tertiary called only on hard failures — 401/403/5xx/timeout, never a plain 429); switching to emergency-only is a one-flag change, not a redeploy of logic
- [ ] Admin Console (5.10) surfaces which failoverMode is active per provider and reminds the admin to flip it the moment primary is upgraded (billing enabled for Gemini, or the free 200 RPM increase for NVIDIA NIM) — genuinely out of scope for this module, belongs to 5.10
- [x] Free-plan workspaces never enter the recurring scheduler — checks are triggered on-demand by the user only, gated by `workspaces.experiments_used` (lifetime cap: 3, never resets); a 4th attempt is blocked outright with an upgrade prompt, never silently queued or allowed
- [x] An on-demand free-tier check runs through the exact same AIProvider / resolveTaskModel / key-pool path as a paid check — no separate cheaper code path, since it is the same Gemini grounded call either way. Note: `enqueueFreeCheck()` exists in `app/src/modules/engine-query/engine-query.ts` and is exported from the module barrel, but no UI/server action calls it yet — wiring an actual "run my free check" button is 5.6's scope (Dashboard/Frontend), not this module's

## Tech

Supabase Edge Functions + pg_cron/pg_net (see decisions log, 2026-07-23 — Railway/Fly.io's free tiers are gone as of this date, so this is no longer an either/or; Edge Functions is the committed approach).

## AI usage

Google Gemini API, Grounding with Google Search.

## Caching

Paid plans: guard against redundant calls by verifying last_checked_at for that (brand, prompt) pair is older than the plan's check interval before enqueueing — a Postgres timestamp check, not a separate cache service. Free plan: no time-based guard applies (there is no recurring cadence) — instead gated by the `workspaces.experiments_used` lifetime counter, checked before allowing an on-demand run.

## Security

Gemini key is server-only, called exclusively from this worker, never from a client-reachable route. Log request counts, never prompt/answer content, in any cross-tenant-visible log.
