## Purpose

Aggregates results into the Visibility Score, Share-of-Voice, and the Explanation Engine (why a competitor wins + Opportunity Finder + confidence-tagged actions) — the product's flagship differentiator.

## Acceptance criteria

- [ ] Visibility Score (0-100), raw mention count, and average rank computed and stored
- [ ] Share-of-Voice vs named competitors, trended weekly
- [ ] Source Influence report (citation domains by type) computed
- [ ] Explanation Engine: percentage breakdown of why a competitor is cited more, via one NVIDIA NIM call per brand per check cycle, model resolved via resolveTaskModel("explanation_generation", workspaceId) against ai_task_configs — not hardcoded in this module
- [ ] Opportunity Finder: gap list of cited source types the brand has zero presence on
- [ ] Recommended actions are confidence-tagged (High/Medium/Low), never stated as flat guarantees
- [ ] Explanation Engine, Opportunity Finder, and recommended actions are computed only for paid-plan workspaces (`workspaces.plan_tier != 'free'`) — gated here, not just hidden in the UI, so Free-plan traffic never triggers the NVIDIA NIM call at all
- [ ] Free-plan workspaces get Visibility Score, mention count, average rank, Share-of-Voice, and Source Influence only; after the 3rd (final) lifetime experiment, one aggregate report is generated combining all 3 runs into a 3-point trend — still without the Explanation Engine

## Tech

Postgres aggregation (SQL) for scoring; one NVIDIA NIM call per brand per cycle for the explanation text.

## AI usage

NVIDIA NIM (same model class as 5.4).

## Caching

Aggregates (score, share-of-voice, explanation) are recomputed only when a new check result lands for that brand — cache the computed result and invalidate on new data, rather than recomputing on every dashboard load.

## Security

Recommendation text is model-generated — label it as guidance in the UI, never as a guarantee, to avoid overstating certainty to customers.
