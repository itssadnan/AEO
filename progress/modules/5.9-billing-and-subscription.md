## Decisions log
_(append-only — date, what was decided, why. Do not delete old entries even if superseded; strike through instead.)_
- **2026-07-23** — Switched billing gateway from Stripe to Razorpay.
  **Why:** Stripe has been invite-only for India-registered businesses since May 2024 and remains so as of mid-2026 (confirmed on Stripe's own India FAQ, support.stripe.com/questions/india-faq) — no self-serve signup, approval not guaranteed. Razorpay offers instant self-serve onboarding, $0 setup fee, $0 AMC, and ~2% domestic / 3% international transaction fee (vs Stripe's 2.9%+$0.30 domestic plus ~1.5–2% international/FX surcharges, plus a 0.7% fee if using Stripe Billing for recurring plans). Razorpay's Subscriptions API + Node.js SDK fit the existing TypeScript/Next.js stack cleanly.
  **Trade-off to remember:** Razorpay has no hosted Customer Portal like Stripe's — the self-serve "change plan / cancel" UI has to be built in-house on top of Razorpay's Subscriptions API rather than dropped in as a vendor-hosted page. Budget dev time for this in module 5.9 implementation.
  **Revisit if:** international customer volume grows enough that VAT/sales-tax compliance in other countries becomes material — at that point, evaluate adding a Merchant-of-Record layer (Dodo Payments or Paddle) on top of/instead of Razorpay rather than treating this as settled permanently.
- **2026-07-23** — Found and fixed a staleness bug while updating 5.10: `docs/architecture/entity-relationship-diagram.md` still had `stripe_customer_id`/`stripe_subscription_id` columns and `system-architecture.md` still said "based on Stripe subscription state" — both left over from before this module's Stripe→Razorpay switch above. Renamed to `razorpay_customer_id`/`razorpay_subscription_id` and updated the prose to match. No functional change, just closing the gap between this decision and the architecture docs.
