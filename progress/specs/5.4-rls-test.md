# Spec: cross-tenant RLS test for `check_extractions` (Module 5.4)

## Context

Module 5.4 (NLP Extraction & Structuring) added `public.check_extractions` in migration `app/supabase/migrations/0013_nlp_extraction_and_structuring.sql`. It has RLS enabled with one policy (`check_extractions_select_member`, workspace-member select only) and no client write policy. Every other Definition-of-Done item for this module has been independently verified except this one: `docs/CONVENTIONS.md` Section 6 item 1 requires "a test proving cross-tenant access is denied — not just filtered in application code," and no such test exists yet for this table.

`app/tests/integration/auth-rls.test.ts` already exists for module 5.1's tables and is explicitly commented as "the template every later module's own RLS test should copy, per Module 5.1's Security note." Read that file first — copy its structure exactly (same env-var-gated `describe.skip` pattern, same admin/anon client setup, same before/after user lifecycle).

## Task

Create `app/tests/integration/nlp-extraction-rls.test.ts` that proves:

1. A workspace member CAN read their own workspace's `check_extractions` rows.
2. A user who is NOT a member of that workspace CANNOT read those rows (RLS filters them out — zero rows returned, not an error, same as `auth-rls.test.ts`'s workspace test).
3. That same non-member cannot write to `check_extractions` at all (no insert/update/delete policy exists for `authenticated` — expect Postgres error code `42501`, same assertion style as `auth-rls.test.ts`'s last test).

## Required fixture setup (do all of this exactly — do not invent a different flow)

Using the pattern from `auth-rls.test.ts`'s `before()` hook:

1. Create two users (A and B) via the admin client, same as the existing test.
2. Sign in as user A (anon client), call `anonForA.rpc("create_workspace", { p_name: "..." })` to get `workspaceAId` — same as the existing test.
3. Still as user A, call `anonForA.rpc("create_brand_with_details", { p_workspace_id: workspaceAId, p_name: "Acme Corp", p_website: "", p_competitor_names: [], p_prompt_texts: ["Best CRM for small business"], p_prompts_ai_suggested: false })` to get `brandAId`. This RPC is `security invoker`, so it runs under user A's own RLS — it will only succeed if A is genuinely a member, which is itself a useful sanity check.
4. Read back the created prompt's id: `anonForA.from("prompts").select("id").eq("brand_id", brandAId).single()` to get `promptAId`.
5. Using the **admin** (service-role) client — because `check_runs` has no client insert policy, same reasoning as `check_extractions` — insert one row into `check_runs`: `workspace_id: workspaceAId, brand_id: brandAId, prompt_id: promptAId, provider: "gemini", model: "test-model", raw_answer: "Acme Corp is a great CRM.", status: "success"`. This insert fires the `check_runs_enqueue_extraction` trigger from migration 0013, which inserts a matching `check_extractions` row automatically — do not insert into `check_extractions` directly.
6. Read back the auto-created extraction row's id via the **admin** client: `admin.from("check_extractions").select("id").eq("check_run_id", <the check_run id>).single()` to get `extractionAId`. You need this id for the read assertions below.

## Tests to write

- `"lets a workspace member read their own workspace's check_extractions row"` — sign in as A, `anonForA.from("check_extractions").select("id").eq("id", extractionAId)`, assert `error` is `null` and `data?.length === 1`.
- `"denies a non-member reading another workspace's check_extractions row"` — sign in as B (who never joined workspace A), same query, assert `error` is `null` and `data?.length === 0`.
- `"denies a non-member inserting into check_extractions"` — sign in as B, attempt `anonForB.from("check_extractions").insert({ check_run_id: crypto.randomUUID(), workspace_id: workspaceAId, brand_id: brandAId, prompt_id: promptAId })`, assert `error?.code === "42501"`.

Clean up in `after()` exactly like `auth-rls.test.ts` does (delete both test users via the admin client — cascades will clean up the workspace/brand/prompt/check_run/check_extraction rows).
